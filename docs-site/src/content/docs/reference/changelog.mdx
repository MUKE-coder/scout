Releases are tagged on [GitHub](https://github.com/MUKE-coder/scout/releases).

## v0.4.17

- **AI / LLM application security** (`code.llm-security`): a new check for insecure
  LLM and agent constructs (OWASP Top 10 for LLM apps) — LangChain/LlamaIndex
  `allow_dangerous_*` flags, Python/shell REPL tools, eval-based chains
  (`LLMMathChain`, `PALChain`), dataframe/SQL agents, and LLM output passed into
  `eval`/`exec` (insecure output handling). Covers Python, JS/TS and notebooks.
  The secrets scanner also now recognises OpenAI, Anthropic, Hugging Face and
  Replicate keys. See [AI / LLM application security](/usage/llm/).

## v0.4.16

- **Self-update** (`scout update`): Scout now keeps itself current. On a normal
  command it checks GitHub at most once a day and, when a newer release is out,
  downloads it, replaces its own binary and relaunches your command on the new
  version — so you are on the latest the next time you run it after a release.
  Run `scout update` to upgrade on demand (`--check` to only look). Skipped in CI,
  for `serve`/`ci`, for dev builds, and when `SCOUT_NO_UPDATE=1`. See
  [Updating Scout](/start/updating/).

## v0.4.15

- **Network sweep** (`network.sweep`, `scout scan --network <cidr>`): scan a whole
  subnet for exposed back-end services — databases, Redis, Docker APIs,
  Elasticsearch, SSH — not just a single host. Scout expands the CIDR, connect-scans
  each host (TCP connect only, no payloads), and reports every open service as one
  graded scan under a target named after the range. IPv4 up to /16; network and
  broadcast addresses skipped. **Only scan networks you are authorized to test.**
  See [Scan a network](/usage/network/).

## v0.4.14

- **Blind command injection** (`app.blind-cmd-injection`): built on the OAST
  listener — Scout injects a benign `curl`/`wget` to its own listener behind shell
  metacharacters and confirms command injection when the callback arrives, even
  when the command's output never shows in the response. Detection only.
- **Supply-chain tamper detection** (`code.obfuscation`): flags the patterns a
  compromised repo shows — install/CI scripts that fetch and run remote code
  (`curl … | sh`, `eval "$(curl …)"`) and obfuscated payloads (`eval(atob(…))`,
  `Function(Buffer.from(…))`, long `String.fromCharCode` chains, dense `\x` hex
  strings). Honours suppression comments; skips legitimate base64 assets.

## v0.4.13

- **Out-of-band testing (OAST)** — `app.blind-ssrf`: Scout now confirms **blind**
  vulnerabilities by observing the target call back. It starts its own OAST
  listener, injects a unique callback URL into candidate parameters, and reports a
  confirmed blind SSRF when the server fetches it — the case the reflected SSRF
  check can't see. The listener is Scout's own (no third-party interaction
  service); it works out of the box for local targets, and takes `SCOUT_OOB_ADDR`
  for a remote, reachable listener. Detection only — Scout observes, never
  exploits. See [Out-of-band testing](/usage/oob/).

## v0.4.12

- **Detection templates** (`app.template`): Scout now runs declarative YAML
  detection templates — a safe, Nuclei-compatible subset — so a new exposed-panel,
  misconfiguration or CVE-signature check is *data*, not Go code. Built-ins ship
  for exposed Apache mod_status, phpinfo and Adminer; add your own with
  `--templates <dir>` (or `SCOUT_TEMPLATES`). Only GET/HEAD detection requests
  run — raw requests, payloads and fuzzing are skipped, so Scout stays detective.
  See [Detection templates](/usage/templates/).
- **`scout scan --repo … --sbom <file>`**: emit the CycloneDX SBOM (with KEV/EPSS)
  as part of a repo scan, without a separate `scout sbom` run.

## v0.4.11

- **`scout sbom`**: generate a **CycloneDX 1.6** software bill of materials for a
  repo, across every supported ecosystem. Scout embeds each component's known
  vulnerabilities — enriched with CISA KEV and FIRST EPSS as CycloneDX properties
  — so the SBOM carries its own exploitation triage, not just a component list.
  `--no-vulns` emits components only; `-o` writes to a file. See
  [Generate an SBOM](/usage/sbom/).

## v0.4.10

- **`code.secrets` skips test fixtures** (issue #7): a weak-pattern secret in a
  test file or doc (a signing key a test must contain) is no longer reported;
  strong cloud-key patterns still fire anywhere. Values that are a URL path or an
  env-var name are treated as references, not credentials.
- **`scout.WithRepo(path)`** (issue #8): a mounted app can attach its project root
  so the dashboard runs the `code.*` collectors against the same target as the
  live checks, in one scan series. Honoured only in the dev environment (a
  dashboard outside dev must not serve source), ignored with a log line otherwise.
- **Laravel detection improved**: the version is read from `composer.json`
  (`Laravel 12.0`) and the `artisan` console script is a definitive marker, so a
  Laravel + Inertia + React app is identified even without a running server.

## v0.4.9

- **Far fewer false positives in the code scanners.** The static checks now honour
  `#nosec` / `biome-ignore` / `eslint-disable` suppressions, skip block comments
  and string literals, and judge intent, not keywords:
  - `code.secret-logging` flags a credential-named **argument** to a log call, not
    the word appearing in a format string (35 → 1 on a real app).
  - `code.dangerous-sink` no longer treats `RegExp.exec` or comments as sinks.
  - `code.insecure-random` fires only when the value is security-relevant, and
    never on `crypto/rand`.
  - `code.weak-crypto` leaves HMAC-SHA1 (RFC 6238 TOTP, AWS SigV4) alone.
  - `code.secrets` ignores URL-path constants whose key happens to contain
    "password".
  - `auth.missing` no longer treats every `/api` route as sensitive, skips
    sign-in/health/webhook/OAuth routes, and honours a `Route.Public` flag.
  - `exposure.dashboards` reports a dashboard only when its **API** answers without
    auth (not the public login shell), and no longer stops at the first probe.

## v0.4.8

- **Expo detection**: Scout now identifies [Expo](https://expo.dev) (React Native)
  apps as a first-class framework — from `eas.json` (or an `expo` key in
  `app.json`), with the version from the `expo` dependency — and reports Expo,
  React and React Native in the stack.

## v0.4.7

- **php2shell detection** (`app.php-runtime-rce`): Scout flags servers running a
  PHP runtime vulnerable to the critical, unauthenticated RCE pair
  **CVE-2026-109618 / CVE-2026-109619** (CVSS 9.2, fixed 2026-10-21). It reads the
  PHP version from the live `Server`/`X-Powered-By` header and from a repo's
  Dockerfile `FROM php:…` base image, and flags anything below PHP 8.2.35 / 8.3.36
  / 8.4.27 / 8.5.12 (and all end-of-life branches).

## v0.4.6

- **Scan a repo straight from its URL**: `scout scan --repo https://github.com/owner/repo`
  now clones the repository to a temporary checkout, scans it, and cleans up.
  Public repos work out of the box; private ones use your existing git
  credentials (`gh auth login`, an SSH key, or a `SCOUT_GIT_TOKEN`/`GITHUB_TOKEN`).

## v0.4.5

- **Target always visible**: the repo or site you are viewing is now shown in the
  top bar on every dashboard page, with a switcher when there is more than one.
  Overview and Stack follow it, and the Findings table gains a Target column — so
  you can always tell which app a view is about.
- **Friendlier repo names**: a `--repo` scan is named after its git remote
  (`owner/repo`) or its folder, instead of the path you happened to pass (`.`).

## v0.4.4

- **Outdated client-side libraries** (`app.vulnerable-js-lib`): a black-box scan
  now flags known-vulnerable front-end libraries the page loads — jQuery,
  Bootstrap, AngularJS, Vue, React, lodash and more. Scout reads the version
  straight from the `<script>`/`<link>` URL (CDN paths and versioned filenames),
  matches it against OSV, and enriches it with KEV + EPSS. No repository needed.

## v0.4.3

- **Exploitation intelligence**: every vulnerable-dependency finding is now
  enriched with **CISA KEV** (is it being exploited in the wild?) and **FIRST
  EPSS** (how likely is exploitation in the next 30 days?). KEV vulnerabilities
  are marked `[Exploited]`, escalated to at least High, and sorted to the top of
  "Fix next" — so you patch what attackers are actually using first. The feeds
  are cached on disk, so repeat scans are fast and work offline.

## v0.4.2

- **Grit framework, first-class**: Scout recognizes a [Grit](https://gritframework.dev)
  monorepo by its `grit.json` and reports the whole stack from it — the Grit
  version and architecture, its Go API and its Next.js/React frontend — so a Grit
  repo scan names the framework and then finds known CVEs across its apps.
- **Dashboard polish**: the per-page recommendation banner is a cleaner, flat
  callout (no rounded box), and the History page spaces its scan cards.

## v0.4.1

- **Framework-aware checks** (`app.framework-exposure`): gated by the detected
  stack, Scout probes Spring Boot actuators, WordPress REST/XML-RPC and Laravel
  debug tools — never probing a framework that was not detected.

## v0.4.0

- **Software composition analysis**: `scout scan --repo .` now matches your
  dependencies against known vulnerabilities across every major ecosystem
  (npm, Go, PyPI, Composer, Cargo, RubyGems, NuGet, Maven) via OSV.
- **Stack detection**: Scout identifies the language, framework and runtime; the
  report shows a stack line and the dashboard has a new "Stack & deps" page.

## v0.3.9

- On-page **"How to scan" guide** and a **dashboard gallery** on the home page.
- `scout lab` fetches only the lab folder (sparse) and scans from there.
- Fix: dashboard coverage commands are correct for repo vs URL targets.

## v0.3.8

- **`scout lab`** clones the vulnerable lab app and scans it in one command.
- A **Recommendation** callout on every dashboard page saying what to do next.
- Scan-coverage is now history-exact (every mode ever run per target).

## v0.3.7

- **Scan coverage** panel on the dashboard: a progress bar over the diagnostic
  dimensions, what each diagnoses, and a Run button or command for the next one.
- **Exports are named after the target** (`scout-<host>-<stamp>.<ext>`).
- Docs: how to read the Attack-surface numbers and Compliance pass/fail, a
  "Scan flags, explained" page, and "what to do" on every dashboard page.

## v0.3.6

- **`scout init`** writes an annotated `scout.yaml` with all defaults.
- **`scout scan --export md,html,txt,json`** writes report files to your working
  directory (findings without opening the dashboard).
- **Green dashboard** to match the docs; a page-by-page [dashboard tour](/usage/dashboard-tour/).

## v0.3.5

- **Dashboard reachable from the root:** `/` and `/scout` now redirect to
  `/scout/ui/`, and `scout serve` prints the URL and "Press Ctrl+C to stop".
- **`--check-timeout`** raises the per-check timeout for slow targets.

## v0.3.4

- **Fix:** `scout scan --serve` no longer panics on a terminal (a double-stop
  of the progress line closed an already-closed channel).

## v0.3.3

- **`scout scan --serve`** runs the scan and then opens the dashboard on the
  same history database (one step from scan to UI). The post-scan hint is
  clearer about the dashboard being a separate server and which DB it reads.

## v0.3.2

- **Export findings** from the dashboard as Markdown, HTML or plain text (plus
  JSON/CSV) — each with the evidence and the fix — to hand to a developer.
- **Installer fix:** the install scripts now put Scout at the front of your PATH
  and warn about an older `scout` that would shadow it.

## v0.3.1

- **Install scripts** for macOS, Linux and Windows, plus prebuilt binaries on
  every release (GoReleaser). `scout version` now reports the real version.
- **Live scan progress** — a spinner with progress and status while a scan runs.
- **Dashboard pointer** printed after a scan, and a redesigned terminal report
  with a readable palette that works in light and dark terminals.
- **New detective checks:** reachable Go CVEs (`code.go-vulncheck`), IDOR with
  test identities (`auth.idor`), version/banner disclosure
  (`app.version-disclosure`), directory listing (`app.directory-listing`),
  missing Subresource Integrity (`app.missing-sri`) and mixed content
  (`app.mixed-content`).
- **Test-identity config surface** — `scout.WithTestIdentities`,
  `core.Target.Identities`, and an `identities:` key in the config file.
- **Active-probe scaffolds** registered for SSTI, XXE, file upload and
  business-logic (inert until their payload logic is written).
- **Embeddable Mount** feeds the real route table into the auth checks, with the
  resolved table exposed at `GET /scout/api/routes`.

## v0.3.0

More coverage and the embedded dashboard. Expanded the check set across headers,
exposure, app, auth and code categories; shipped the React dashboard compiled into
the binary; added the deliberately-vulnerable lab app under `lab/`.

## v0.2.0

Core engine and the first collectors. Mode caps, environment gating, ownership
verification, SARIF output, scan history in SQLite, and `scout ci` for pipeline
gating.

## v0.1.0

Initial release — the CLI skeleton, the check registry, and the first passive
checks.
