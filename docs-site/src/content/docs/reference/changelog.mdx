description: What changed in each Scout release.

Releases are tagged on [GitHub](https://github.com/MUKE-coder/scout/releases).

## v0.4.5

- **Target always visible**: the repo or site you are viewing is now shown in the
  top bar on every dashboard page, with a switcher when there is more than one.
  Overview and Stack follow it, and the Findings table gains a Target column — so
  you can always tell which app a view is about.
- **Friendlier repo names**: a `--repo` scan is named after its git remote
  (`owner/repo`) or its folder, instead of the path you happened to pass (`.`).

## v0.4.4

- **Outdated client-side libraries** (`app.vulnerable-js-lib`): a black-box scan
  now flags known-vulnerable front-end libraries the page loads — jQuery,
  Bootstrap, AngularJS, Vue, React, lodash and more. Scout reads the version
  straight from the `<script>`/`<link>` URL (CDN paths and versioned filenames),
  matches it against OSV, and enriches it with KEV + EPSS. No repository needed.

## v0.4.3

- **Exploitation intelligence**: every vulnerable-dependency finding is now
  enriched with **CISA KEV** (is it being exploited in the wild?) and **FIRST
  EPSS** (how likely is exploitation in the next 30 days?). KEV vulnerabilities
  are marked `[Exploited]`, escalated to at least High, and sorted to the top of
  "Fix next" — so you patch what attackers are actually using first. The feeds
  are cached on disk, so repeat scans are fast and work offline.

## v0.4.2

- **Grit framework, first-class**: Scout recognizes a [Grit](https://gritframework.dev)
  monorepo by its `grit.json` and reports the whole stack from it — the Grit
  version and architecture, its Go API and its Next.js/React frontend — so a Grit
  repo scan names the framework and then finds known CVEs across its apps.
- **Dashboard polish**: the per-page recommendation banner is a cleaner, flat
  callout (no rounded box), and the History page spaces its scan cards.

## v0.4.1

- **Framework-aware checks** (`app.framework-exposure`): gated by the detected
  stack, Scout probes Spring Boot actuators, WordPress REST/XML-RPC and Laravel
  debug tools — never probing a framework that was not detected.

## v0.4.0

- **Software composition analysis**: `scout scan --repo .` now matches your
  dependencies against known vulnerabilities across every major ecosystem
  (npm, Go, PyPI, Composer, Cargo, RubyGems, NuGet, Maven) via OSV.
- **Stack detection**: Scout identifies the language, framework and runtime; the
  report shows a stack line and the dashboard has a new "Stack & deps" page.

## v0.3.9

- On-page **"How to scan" guide** and a **dashboard gallery** on the home page.
- `scout lab` fetches only the lab folder (sparse) and scans from there.
- Fix: dashboard coverage commands are correct for repo vs URL targets.

## v0.3.8

- **`scout lab`** clones the vulnerable lab app and scans it in one command.
- A **Recommendation** callout on every dashboard page saying what to do next.
- Scan-coverage is now history-exact (every mode ever run per target).

## v0.3.7

- **Scan coverage** panel on the dashboard: a progress bar over the diagnostic
  dimensions, what each diagnoses, and a Run button or command for the next one.
- **Exports are named after the target** (`scout-<host>-<stamp>.<ext>`).
- Docs: how to read the Attack-surface numbers and Compliance pass/fail, a
  "Scan flags, explained" page, and "what to do" on every dashboard page.

## v0.3.6

- **`scout init`** writes an annotated `scout.yaml` with all defaults.
- **`scout scan --export md,html,txt,json`** writes report files to your working
  directory (findings without opening the dashboard).
- **Green dashboard** to match the docs; a page-by-page [dashboard tour](/usage/dashboard-tour/).

## v0.3.5

- **Dashboard reachable from the root:** `/` and `/scout` now redirect to
  `/scout/ui/`, and `scout serve` prints the URL and "Press Ctrl+C to stop".
- **`--check-timeout`** raises the per-check timeout for slow targets.

## v0.3.4

- **Fix:** `scout scan --serve` no longer panics on a terminal (a double-stop
  of the progress line closed an already-closed channel).

## v0.3.3

- **`scout scan --serve`** runs the scan and then opens the dashboard on the
  same history database (one step from scan to UI). The post-scan hint is
  clearer about the dashboard being a separate server and which DB it reads.

## v0.3.2

- **Export findings** from the dashboard as Markdown, HTML or plain text (plus
  JSON/CSV) — each with the evidence and the fix — to hand to a developer.
- **Installer fix:** the install scripts now put Scout at the front of your PATH
  and warn about an older `scout` that would shadow it.

## v0.3.1

- **Install scripts** for macOS, Linux and Windows, plus prebuilt binaries on
  every release (GoReleaser). `scout version` now reports the real version.
- **Live scan progress** — a spinner with progress and status while a scan runs.
- **Dashboard pointer** printed after a scan, and a redesigned terminal report
  with a readable palette that works in light and dark terminals.
- **New detective checks:** reachable Go CVEs (`code.go-vulncheck`), IDOR with
  test identities (`auth.idor`), version/banner disclosure
  (`app.version-disclosure`), directory listing (`app.directory-listing`),
  missing Subresource Integrity (`app.missing-sri`) and mixed content
  (`app.mixed-content`).
- **Test-identity config surface** — `scout.WithTestIdentities`,
  `core.Target.Identities`, and an `identities:` key in the config file.
- **Active-probe scaffolds** registered for SSTI, XXE, file upload and
  business-logic (inert until their payload logic is written).
- **Embeddable Mount** feeds the real route table into the auth checks, with the
  resolved table exposed at `GET /scout/api/routes`.

## v0.3.0

More coverage and the embedded dashboard. Expanded the check set across headers,
exposure, app, auth and code categories; shipped the React dashboard compiled into
the binary; added the deliberately-vulnerable lab app under `lab/`.

## v0.2.0

Core engine and the first collectors. Mode caps, environment gating, ownership
verification, SARIF output, scan history in SQLite, and `scout ci` for pipeline
gating.

## v0.1.0

Initial release — the CLI skeleton, the check registry, and the first passive
checks.
